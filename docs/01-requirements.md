# 01 需求理解与拆解

## 题目背景

小影内容团队每天有大量待发布素材（视频/图文），发布前需要完成三件事：

1. **素材信息核对**：素材元数据（标题、时长、审核状态、文案）是否完整；
2. **审核规则检查**：是否命中违禁词、是否通过人工审核、时长是否超限；
3. **发布时段确认**：用户要求的日期/时段是否与已排期内容冲突。

当前流程由人工逐一核对，效率低、易漏检。本题要求构建一个 AI Agent，自动完成素材审核与发布排期，产出**待用户确认的排期草稿**。

## 核心目标

给定一个排期任务（素材 ID + 要求的发布日期/时段），Agent 自主完成：

```
读取素材 → 检查规则 → 查询时段 → 保存草稿（或说明风险） → 汇报结果
```

## 需求拆解

### 功能需求

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F1 | 素材读取 | 按素材 ID 读取元数据；素材不存在时明确返回失败 |
| F2 | 规则检查 | 必填字段完整性、审核状态白名单、时长上限、违禁词 |
| F3 | 时段查询 | 查询某日期某整点时段是否被占用，返回占用者信息 |
| F4 | 草稿保存 | 保存待确认排期草稿；目标时段被占用时拒绝保存 |
| F5 | 冲突处理 | 要求时段被占用时，查询相邻整点时段，找到空闲替代并说明待确认原因 |
| F6 | 结果汇报 | 最终结果必须可追溯到工具观察结果，不得编造 |

### 硬性边界（不可违反）

| 编号 | 边界 |
| --- | --- |
| B1 | 只保存草稿，**绝不发布**；任何输出不得声称"已发布" |
| B2 | 未经用户同意，不得更改用户指定的日期/时段（替代时段必须标注待确认） |
| B3 | 保存失败必须如实返回失败，不得谎报成功 |
| B4 | 同一素材重复提交只保留一份草稿（幂等） |
| B5 | 素材信息缺失或规则风险时阻断排期，说明原因并转人工 |
| B6 | 执行步数/调用次数有上限，超限返回明确的"未完成"状态 |

### 验收点（来自题目）

| # | 验收点 | 对应示例 |
| --- | --- | --- |
| 1 | 正常排期（无冲突） | M01 @ 2026-11-05 18:00 冲突 → 建议 19:00（含冲突处理，同时验证正常保存链路） |
| 2 | 素材信息缺失 | M02 缺 duration_sec |
| 3 | 规则风险 | M03 违禁词 |
| 4 | 时段冲突与替代建议 | case1 |
| 5 | 重复提交去重 | case5 |
| 6 | 保存失败如实返回 | case6 |

## 输入 / 输出约定

**输入（任务）**：

```json
{"material_id": "M01", "requested_date": "2026-11-05", "requested_time": "18:00"}
```

}
